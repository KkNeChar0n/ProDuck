# 默认新建与编辑体验验收

2026-11-25，Produck 0.1.22。

## 行为

默认目标包含新建和编辑。每个识别模块的两类流程各自有五项清单：入口、字段与默认值/回填、校验约束、取消、保存后结果。清单随任务保存、支持暂停恢复，在界面与理解 Markdown 展示，不由报告生成覆盖。

模型根据实际观察评估覆盖；宿主检查采集 ID，保存还要求同模块同流程存在已执行的提交与后续页面引用。单纯填写、打开弹窗、确认后失败或校验阻止都不等同保存成功。模型提前结束但仍有未说明原因的遗漏时，最多要求继续两次；预算耗尽、用户拒绝、权限不足或入口未找到均保留未勾选项。即便清单全部勾选，也不意味着所有异常、权限和业务校验分支已验证。

编辑优先使用本轮新建的测试记录或用户指定记录，提交仍有单次确认；删除不是常规体验。共用表单以对话框语义标题区分新建和编辑，同一上下文内改值或换回车不会解除防重放。旧格式任务保守处理，不推断旧记录已完成。

## 确定性验证

- 单元测试验证清单初始化、伪造引用拒绝、未提交/未执行/没有后续观察时不记保存完成、部分覆盖及限制保留、序列化后清单保持、两次提前结束检查。
- 真实 Chrome 的 `discovery-crud-smoke.mjs` 使用 `customers-crud.html` 虚构页面：新建修改后取消、新建校验与保存、编辑回填、修改后取消保留原数据、编辑必填校验、回车保存后负责人更新。新建和编辑复用同一弹窗和表单，仅标题不同；同一编辑重复保存被阻止。
- 原浏览器探索回归、桌面无 CLI 原型/PRD/平台模拟流程继续验证。浏览器旧测试模型不提供深度清单，故报告保留未覆盖，不能将该模拟测试解读为深度流程已完成。

证据：[真实 Chrome CRUD](discovery-crud-smoke.json)。运行 `npm run test:discovery:crud`。

## 本轮真实模型验证

调用当前项目已配置模型 `gpt-6.1-sol`，仅使用临时项目和本地虚构页面，关注目标为空，预算 40 步。模型主动识别客户模块，先新建测试记录，再编辑该记录；实际使用 19 个页面状态，两次测试专用确认后完成保存。清单中两类流程均记录五项覆盖，仍注明业务校验和未发现入口的限制。

可观察结果包括：新建取消后未增加记录，新建成功后从 3 行增加到 4 行；编辑回填正确，清空必填字段后原生有效性变为无效；取消保留原记录；重新编辑保存后负责人更新，页面显示更新反馈。还体验了名称查询、组合状态筛选与重置。未执行删除，未批准草稿为长期记忆。

首次实验中模型把 browse 放进只允许 create/edit 的清单，旧错误处理暂停。改为反馈无效清单并继续探索后，第二轮首步反馈错误、后续模型给出有效清单并完成上述流程。最终增加的“必须是提交动作”校验由单元测试及最终包回归验证；本轮真实模型执行记录保留开发过程原始字段，不改写为后续格式。

证据：[真实模型步骤与清单](discovery-depth-live.json)。复现命令：

```sh
npm run build
node scripts/live-discovery-check.mjs --use-configured-model --deep
```

这会使用当前项目模型并产生模型用量，凭证仅在钥匙串和请求内使用。测试确认回调仅针对无后台的本地夹具，不替代应用内用户对真实保存的确认。

## 范围

这是单模块合成页面的深度体验验证，不能外推为任意系统完整覆盖。自定义组件、跨域流程、复杂字段联动、不同权限和服务端校验仍需逐站验证。无语义标题的复用表单可能被保守视为同一提交。默认 40 步，上限 120；建议复杂系统按模块分轮。

最终安装包测试通过：1962 个运行资源前后哈希一致，系统 CLI 不可用时桌面流程完成。修正了测试在开始按钮禁用时点击的竞态；应用代码不因该测试修正而变化。
