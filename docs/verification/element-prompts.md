# 导航与批量元素修改验收

2026-11-23，Produck 0.1.16。

## 使用方法

- 交接资料入口：选择项目及版本 → 工作台 → 交接资料 → 导入交接资料。支持 Markdown、文本和 HTML，资料归项目共享。
- 工作流入口：启动多步骤 Agent 任务、逐项确认操作，查看任务记录并恢复中断任务；不是导入资料的入口。
- 标题栏左上角按钮可收起导航以扩大工作台，再次点击可展开（2026-11-24 移除重复的左栏按钮）。
- 打开原型，右侧「调整原型 → 拾取元素」，依次点击目标，为每张卡片填写要求；可移除、重新拾取，最多 12 个元素。整体补充要求可选。点击「提交 N 处」统一生成一个候选，体验后再通过版本。
- 切换原型会清空当前选择；失败或取消保留输入。同一元素重复点击不会产生重复卡片。运行时动态元素使用最近的带稳定 ID 父区域；不存在于保存基线的 ID 拒绝提交。

## 验证证据

- 类型检查、构建通过；92 项单元测试，91 通过，1 项需独立启用的原生 Python 测试跳过。
- 批量目标校验覆盖旧版本、内容变化、未知/重复/歧义 ID、空要求和数量/长度上限。
- 重启任务重试测试确认模型再次收到原始两条元素绑定。
- Electron 无 CLI 回归：同一事件循环连续选择标题和按钮，右侧得到两张卡片；模拟模型首次失败后两条输入保留，重新提交后新候选标题和按钮分别变化，详情中的 ID、prompt、基线和哈希与输入一致。旧原型批准保持，新候选未批准。
- 收起导航使工作台宽度增加超过 100 像素，再通过标题栏展开。
- 模型为本地模拟端点，证明绑定、持久化和交互链路，不代表真实模型修改质量。
- `desktop-element-prompts.png` 展示两张修改卡片。主窗口截图不包含独立原生预览层；`desktop-prototype.png` 单独保存生成后的原型画面。

安装包验证结果见 release-readiness.md；测试包保持 ad-hoc 签名，未公证。
