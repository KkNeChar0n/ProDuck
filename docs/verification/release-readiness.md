## 安装验收记录模板

在待验收机器上记录：系统版本、芯片、安装包版本及 SHA-256、安装/首次启动结果。按顺序创建项目、配置模型、创建产品版本、采集代表页面、生成候选、体验检查并通过、截图与 PRD 草稿、退出重启、恢复基线、导入 Python 示例并授权执行。每步记录通过/失败、截图、错误信息及成果路径。

真实平台测试另行使用测试项目，在项目设置填写凭证，在版本设置填写飞书迭代地址。发布前核对父节点，发布后记录链接及读回；云效核对工作项与映射状态。不要把 token、App Secret 或 PAT 写入验收记录。

## 签名、公证与许可

当前安装包只有 ad-hoc 签名，未公证，不属于公开分发版本。正式分发需要 Developer ID Application 身份、相应签名配置、notarytool 可用凭证、公证成功及 stapler 验证，还需在非开发机器验证 Gatekeeper 和首次启动。

项目代码为 MIT。已观察运行包的声明：Electron、React、React DOM、scheduler、parse5 为 MIT；entities 为 BSD-2-Clause。Electron/Chromium 聚合通知和各包原许可随包保留。Python 来源及校验值固定，CPython LICENSE.txt 与分发中现有通知保留。

`runtime-licenses.json` 是扫描记录，包含声明版本和实际通知文件哈希，不是完整许可合规结论。已从相同版本/架构的完整构建归档提取元数据引用的 14 份原生组件许可文本，并核对解释器及 10 个动态库/扩展文件哈希一致，随包保留于 Python 的 PRODUCK-LICENSES 目录。2026-11-19 本机查询结果为 0 个有效代码签名身份；正式签名、公证与分发验证未完成，因此 8.5 保留未完成。原 PRD 技能未提供明确再分发许可的脚本没有复制进仓库。
