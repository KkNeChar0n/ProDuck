# 飞书首次发布与恢复（0.1.4）

2026-11-18；任务 6.3 完成，总体 33/47。上一轮官方文档获取障碍已解除。

## 行为

在文档页准备并确认审阅包后，填写标题并点击“发布到飞书”。系统确认框展示父节点、标题和写入范围。每次写操作前重新核对本地材料及配置；凭证只在主进程申请临时访问令牌，不进入审阅包或收据。

发布在迭代父节点追加共用 HTML 附件块，创建需求子节点，写入正文、父节点入口和对应截图。正文保留 Markdown 原文分段，不声称已转换成复杂富文本排版。图片作为独立素材上传。已存在相同原型时复用并下载核验；不同原型需走后续差异合并，不在首次发布中覆盖。

完成前核对文档归属、正文和入口链接、图片与文件块 token，再下载图片及原型文件比对 SHA-256。服务器改写文件或拒绝下载会导致核对失败，不显示成功。单个文件限 20 MB；不自动跟随下载重定向。真实租户可能需要补充素材读取权限。

## 恢复与限制

`workflows/publications.json` 保存运行 ID、材料指纹、阶段请求 ID、远端节点/块/素材 ID 和状态。写前落盘 pending，返回后保存结果。重启不自动执行，用户再次确认后核对并继续。

创建文档响应丢失时按稳定标题标记查询同一父节点；块创建响应丢失时查找标记及连续块结构；绑定响应丢失时核对已保存素材 token。只有匹配唯一结果才采纳。上传结果未知且拿不到 token 时保留“待核对”，不自动重传，目前没有人工收据补录界面。已确认步骤不再写入；同一草稿不能通过另建审阅包重复创建文档。

这是首次发布的恢复能力。线上章节合并、附件更新、云效同步和跨平台失败恢复尚未实现，6.4–6.8 保持未完成。真实租户与真实模型质量未验收；本次没有调用用户模型或写入真实飞书。

## 验证

54 项单元测试、类型检查、构建、原生 Electron 桌面流程通过。覆盖完整首次发布、重复操作不增加远端写入、创建成功后响应丢失、上传结果未知、读回正文被修改、共用原型冲突、未批准材料拦截、API 参数与错误脱敏。桌面测试使用临时 profile、虚构钥匙串凭证和内存飞书服务，实际经过确认对话框、全部 IPC 与请求序列，完成 8 个阶段；截图为 desktop-published.png。

## 接口依据

只检查官方 SDK 类型/请求实现，没有添加 SDK 依赖或执行其代码。使用自有小型 HTTP 适配器。

- 官方包：`@larksuiteoapi/node-sdk@1.76.0`，https://registry.npmjs.org/@larksuiteoapi/node-sdk/-/node-sdk-1.76.0.tgz
- 创建块：https://open.feishu.cn/document/ukTMukTMukTM/uUDN04SN0QjL1QDN/document-docx/docx-v1/document-block-children/create.md
- SDK 定义核对：wiki spaceNode.create/list、docx documentBlockChildren.create/list、documentBlock.patch、drive media.uploadAll/download。
