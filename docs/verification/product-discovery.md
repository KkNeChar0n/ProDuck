# Chrome 产品理解与长期记忆验收

2026-11-24，Produck 0.1.20。对应 OpenSpec `product-discovery`。

## 用户流程

1. 选择项目和产品版本；如有交接文档，先在「工作台 → 交接资料」导入。
2. 打开「工作台 → 理解产品」，填写地址，点击「打开独立 Chrome」。使用本机 Google Chrome，无需开发工具、调试端口或额外扩展。
3. 在独立窗口登录并停在产品首页。回到 Produck 填写关注范围（可选），点击「授权并开始自动体验」。默认 12 步，可选 2–30 步。
4. Agent 根据页面元素自行选择查看、模块导航、筛选、详情等动作，并记录页面截图、结构、动作及未覆盖部分。普通操作失败会重新观察或换路；涉及业务变更时单次确认，确认后由 Agent 执行。连续失败会整理已有依据。
5. 审核 Markdown 中的产品概览、模块职责、流程、依据、冲突与待确认事项。可编辑后保存修订；只有点击审核通过才写入项目长期记忆。
6. 「审核通过并生成原型」将多页依据与同一批准理解用于统一模拟原型。生成后自动切到原型页，可以使用已有元素拾取与修改流程。也可先仅保存记忆，稍后生成。

「浏览器 → 采集当前状态」仍为手动单页补充入口，不代表自动理解整个产品。

## 数据与范围

- Chrome 按项目独立保存配置和登录状态，正常退出时关闭自有 Chrome 并刷新浏览器数据；网站会话到期或主动注销后仍需重新登录。不会读取或复制日常 Chrome 配置。
- 理解任务及报告位于项目 `discovery/runs`、`discovery/reports`；MD 与 JSON 成对保存。`memory/产品理解索引.md` 和根 `记忆.md` 引用已审核理解。普通问答自动参考活跃理解，Agent 的 `search_memory` 可检索它。
- 报告审核绑定正文、页面证据及截图摘要；修订创建新文件，原批准版保留。新一轮未经审核的观察不会覆盖长期记忆。生成原型记录报告 ID/摘要及全部采集 ID；原型归当前固定产品版本。
- 自动动作支持当前站点的通用控件、输入与键盘，不再使用控件名称白名单。识别出的业务提交由宿主单次确认，拒绝后继续探索其他入口；已尝试的业务操作不自动重放。登录仍由用户完成。HTTP 方法本身不是无副作用保证，不能将自动模式视为真实业务接口的通用只读沙箱。
- 允许普通 POST 查询；明显变更路径、GraphQL mutation 和其他写入方法需要当前动作确认。未识别的自定义接口仍可能产生副作用，不能保证拦截所有写入；记录中会显示被阻止请求。跨域页面、iframe、Canvas 和不提供可识别元素的控件可能需要手动补充。
- 单轮最多 30 个页面状态。单份资料读取前 4000 字、资料合计前 10000 字，最多 50 份；截断或未读资料在报告标明。长页面与结构也有上下文上限。
- 本轮理解和原型仍以文字、DOM 结构与样式为模型输入，截图留在本地核对。真实模型的理解深度、视觉还原和复杂站点覆盖程度需要实际产品验收。

## 验证

- 单元测试覆盖动作/请求边界、跨项目访问拒绝、未审核拒绝生成、精确批准、修订后旧记忆保留、证据变动失效、断网续接不重放、取消时保留证据。
- `npm run test:discovery` 使用真正 Chrome 和临时独立配置访问本地测试站点：登录保留、项目隔离、自主切换侧栏、客户详情与订单导航、四份页面采集、交接资料综合、审核后多来源候选原型、POST 查询、通用输入与键盘、拒绝写入、确认后仅执行一次及未确认的明显写入拦截全部通过。模型为受控测试响应。
- Electron UI 测试实际打开 Chrome，从默认入口开始理解，修改并保存 Markdown，审核后自动生成原型、查看项目记忆，并验证普通问答收到人工修订内容。仍验证原有原型、PRD、飞书、云效和 Python 流程。
- 安装包测试会使用本机已安装的 Chrome，但禁用系统 Node/Python/Codex/Claude CLI；在 DMG 提取副本中运行同一桌面流程。该测试不等同全新 Mac 上的首次安装验证。
