# Chrome 产品理解与长期记忆验收

2026-11-24，Produck 0.1.23。对应 OpenSpec `product-discovery`。

## 用户流程

1. 选择项目和产品版本；如有交接文档，先在「工作台 → 交接资料」导入。
2. 打开「工作台 → 理解产品」，填写地址，点击「打开独立 Chrome」。使用本机 Google Chrome，无需开发工具、调试端口或额外扩展。
3. 在独立窗口登录并停在产品首页。回到 Produck 填写关注范围（可选），点击「授权并开始自动体验」。默认 40 步，可选 2–120 步。
4. Agent 根据页面元素自行选择查看、模块导航、筛选、详情等动作，并记录页面截图、结构、动作及未覆盖部分。普通操作失败会重新观察或换路；涉及业务变更时单次确认，确认后由 Agent 执行。连续失败会整理已有依据。
5. 审核 Markdown 中的产品概览、模块职责、流程、依据、冲突与待确认事项。可编辑后保存修订；只有点击审核通过才写入项目长期记忆。
6. 「审核通过并生成原型」将多页依据与同一批准理解用于统一模拟原型。生成后自动切到原型页，可以使用已有元素拾取与修改流程。也可先仅保存记忆，稍后生成。

「浏览器 → 采集当前状态」仍为手动单页补充入口，不代表自动理解整个产品。

## 数据与范围

- Chrome 按项目独立保存配置和登录状态，正常退出时关闭自有 Chrome 并刷新浏览器数据；网站会话到期或主动注销后仍需重新登录。不会读取或复制日常 Chrome 配置。
- 理解任务及报告位于项目 `discovery/runs`、`discovery/reports`；MD 与 JSON 成对保存。`memory/产品理解索引.md` 和根 `记忆.md` 引用已审核理解。普通问答自动参考活跃理解，Agent 的 `search_memory` 可检索它。
- 报告审核绑定正文、页面证据及截图摘要；修订创建新文件，原批准版保留。新一轮未经审核的观察不会覆盖长期记忆。生成原型记录报告 ID/摘要及全部采集 ID；原型归当前固定产品版本。
- 自动动作支持当前站点的通用控件、输入与键盘，不再使用控件名称白名单。识别出的业务提交由宿主单次确认，拒绝后继续探索其他入口；已尝试的业务操作不自动重放。登录仍由用户完成。HTTP 方法本身不是无副作用保证，不能将自动模式视为真实业务接口的通用只读沙箱。
- 允许普通 POST 查询；明显变更路径、GraphQL mutation 和其他写入方法需要当前动作确认。未识别的自定义接口仍可能产生副作用，不能保证拦截所有写入；记录中会显示被阻止请求。跨域页面、iframe、Canvas 和不提供可识别元素的控件可能需要手动补充。
- 单轮最多 120 个页面状态。单份资料读取前 4000 字、资料合计前 10000 字，最多 50 份；截断或未读资料在报告标明。长页面与结构也有上下文上限。
- 本轮理解和原型仍以文字、DOM 结构与样式为模型输入，截图留在本地核对。真实模型的理解深度、视觉还原和复杂站点覆盖程度需要实际产品验收。

## 验证

- 单元测试覆盖动作/请求边界、跨项目访问拒绝、未审核拒绝生成、精确批准、修订后旧记忆保留、证据变动失效、断网续接不重放、取消时保留证据。
- `npm run test:discovery` 使用真正 Chrome 和临时独立配置访问本地测试站点：登录保留、项目隔离、自主切换侧栏、客户详情与订单导航、六份页面采集（含提前结束检查）、交接资料综合、审核后多来源候选原型、POST 查询、通用输入与键盘、拒绝写入、确认后仅执行一次及未确认的明显写入拦截全部通过。模型为受控测试响应。
- Electron UI 测试实际打开 Chrome，从默认入口开始理解，修改并保存 Markdown，审核后自动生成原型、查看项目记忆，并验证普通问答收到人工修订内容。仍验证原有原型、PRD、飞书、云效和 Python 流程。
- 安装包测试会使用本机已安装的 Chrome，但禁用系统 Node/Python/Codex/Claude CLI；在 DMG 提取副本中运行同一桌面流程。该测试不等同全新 Mac 上的首次安装验证。

记录：`product-discovery-smoke.json`、`desktop-discovery-review.png`、`desktop-understanding-memory.png`、`packaged-runtime.json`。模型与平台凭证没有写入仓库。

## 0.1.21 表单修复

元素观察增加关联标签、普通字段值、选中状态、必填与原生校验信息。明确的查询表单可重复提交；判断需要搜索语义、查询按钮且没有敏感字段或明显写入目标，模型声明为只读不能解除业务确认。

回车事件补齐字符语义。业务表单以页面及表单身份记录尝试，保存按钮与输入框回车共享记录；修改字段不会解除已经尝试或拒绝的提交。原生无效表单在任何点击/按键事件派发前返回校验失败，允许填写后继续。自定义 JavaScript 校验、结果不明或已经执行的提交不适用此例外。旧任务缺少表单身份时保守阻止业务续提，可重新开始理解。

`npm run test:discovery:forms` 验证真实 Chrome 的重复查询、回车查询与保存、字段状态、无效表单零点击事件、拒绝/尝试后的跨入口保护；任务恢复保护由单元测试覆盖。该机制仍非通用只读网络沙箱，也不保证自定义组件的完整覆盖。

实现入口：`src/discovery/chrome.ts`（观察与执行）、`browser-policy.ts`（操作分类与身份）、`service.ts`（模型循环、持久记录和恢复），类型在 `src/contracts/discovery.ts`。修改源码后重新构建安装包才会覆盖已安装应用；项目记忆不会修改 harness 代码。


## 0.1.22 默认深度体验

新建与编辑现在是默认流程，无需在关注范围另行点名。Agent 先识别模块，再逐模块体验入口、字段及默认值/回填、校验约束、修改后取消、保存后的结果。编辑优先选本轮新建的测试记录或用户指定测试记录；真实业务提交保持确认，删除不属于默认体验。

界面和理解 Markdown 都显示持久化覆盖清单，区分已观察与未完整覆盖，并列出依据及限制。观察评估来自模型，宿主拒绝虚构采集 ID；保存覆盖还必须对应同模块同流程的已执行业务提交和后续采集。无效清单反馈给模型修正，不中断普通探索；最多两次纠正过早结束，仍有遗漏则如实输出不完整报告。用户拒绝、权限不足、入口未找到和预算耗尽都不能算完整体验。支持最多 12 个识别模块，新建/编辑各一行；复杂系统建议按模块分轮。

默认 40 步、上限 120；更多步数增加时间和模型用量，并不保证全部异常分支覆盖。报告模型只接收最近 40 步摘要及受限的页面摘录，完整记录和新建/编辑覆盖清单保留在宿主。Markdown 上限扩为 60000 字；原型生成仍使用有长度上限的报告上下文。

新建与编辑复用同一原生表单时，对话框标题参与操作身份识别；仅修改字段不能绕过同一流程的防重放。缺少语义标题的自定义表单仍可能保守阻止后续提交并标记未覆盖，不能保证任意自定义组件。

验证入口：`npm run test:discovery:crud`（真实 Chrome 合成页面），`node scripts/live-discovery-check.mjs --use-configured-model --deep`（使用当前项目真实模型，仅发送虚构页面，产生模型用量）。详见 [深度体验验收](discovery-depth.md)。


## 0.1.23 草稿后继续探索

本轮生成草稿后，点击「继续探索」继承页面依据、资料快照、新建/编辑清单和已尝试业务操作记录，优先补齐缺失项；新增步数使用上方输入值，默认 40、每轮 2–120。界面同时显示本轮进度和累计状态。120 是单轮上限，不再是续探链的累计状态上限。

续探创建关联的新任务快照，不修改旧任务，因此旧报告摘要与已审核记忆仍有效。新报告重新审核后才替换活跃记忆；草稿有未保存修改时需先保存，续探参考上轮最新修订。关闭 Chrome 后先重新打开原站点；意外中断仍使用「授权并继续自动体验」恢复当前轮次。

「重新探索」独立建立新清单，适合系统已更新。历史任务与报告继续保留，但不继承本次体验覆盖。报告模型只读取最近 120 个页面和最近 40 步的有界摘要，完整累计依据及操作记录仍保存于任务，已有模块数量和组件支持范围仍适用。

验证：104 项单元测试中 103 通过、1 项原生 Python 默认跳过；覆盖继承、预算增加、跨项目拒绝、并发拒绝、旧批准仍可读取、续探防重放、新草稿不自动替换记忆均通过。桌面测试实际点击续探按钮并完成第二轮草稿，再验证旧记忆问答可用。截图：[继续探索](desktop-discovery-continue.png)。本轮验证使用合成页面及受控模型响应，不作为新增真实模型质量证明。
