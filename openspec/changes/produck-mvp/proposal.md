## 为什么

产品经理在理解已有系统、制作交互原型、编写需求和推进云效工作项之间反复切换工具，页面、文档和项目知识容易脱节。Produck 将这些工作组织成可追溯的项目流程，首版供发起人自用，并保留后续分发给其他产品经理的能力。

## 变更内容

- 提供米白色、三栏式 macOS 桌面工作台；安装后配置模型即可使用核心能力，无需自行安装开发工具或 Agent CLI。
- 支持模型供应商、Base URL、模型和 token 配置，以及每项目独立工作空间、飞书和云效连接。
- 读取交接文档或体验已登录网页，记录页面依据和项目记忆，重建使用模拟数据的高保真可操作原型。
- 通过页面或元素选择与右侧 prompt 修改原型，支持对比、撤销和版本确认。
- 按已确认原型撰写 PRD；修改线上文档时读取实时内容、评审差异后合并，成功后同步工作项。
- 支持 Codex / Claude 风格的 SKILL.md 及附属资源；内置首批产品工作流，明确报告第三方技能依赖和兼容性。
- 建立可恢复任务记录和适配器边界，使用单仓库、单应用的模块化结构。
- 首版不包含多人协作、云端账号体系、插件市场、真实业务后端复刻或任意第三方技能的无条件兼容。

## 功能 (Capabilities)

### 新增功能

- `desktop-workspace`: 桌面安装、工作台、项目隔离与本地存储。
- `agent-runtime`: 模型连接、工具执行、凭证保护和任务恢复。
- `product-understanding`: 文档与网页采集、有来源的项目记忆。
- `prototype-workbench`: 可操作原型重建、元素修改和确认版本。
- `delivery-workflow`: PRD 生成、差异评审、飞书发布及云效同步。
- `skill-compatibility`: 技能发现、工具适配、依赖检查和内置工作流。

### 修改功能

无，当前仓库尚无实现或既有功能规范。

## 影响

- 新增桌面应用、Agent 执行层、本地持久化、浏览器和平台适配器，以及安装包构建流程。
- 对接用户配置的模型 API、飞书及云效；模型调用需要网络，平台发布需要对应凭证。
- 本地保存项目资料、记忆、原型、文档和任务状态；凭证存入 macOS 钥匙串。
- 使用现有 PRD skills 的原型先行、版本固定、实时读取和差异评审规则作为流程依据，并适配为应用内能力。
