## 上下文

仓库目前只有 README、LICENSE 和 OpenSpec 配置，无历史应用或数据需要兼容。首版用于个人真实产品工作，后续分发给其他产品经理。核心约束为 macOS 安装即用、高保真模拟交互、项目隔离、可追溯成果与适度扩展。

## 目标 / 非目标

**目标：** 完整打通资料理解、原型修改、版本确认、文档评审和平台同步；本地保存成果；新增供应商或平台无需修改界面与流程核心；无需用户安装开发工具。

**非目标：** 多租户服务、多人实时协作、插件市场、自动实现业务后端、任意站点源码恢复、全部第三方技能零适配运行。

## 决策

### 1. 单仓库模块化桌面应用

采用 Electron、React、TypeScript，使用主进程管理窗口、凭证和受控 IPC，独立执行进程处理模型循环与长任务。选择 Electron 是因为 Chromium 页面体验和本地工具是核心需求；Tauri 体积更小，但浏览器兼容和自动化需要额外整合；纯原生方案会增加前端原型复用成本。

建议目录：`src/desktop`（主进程与 preload）、`src/ui`、`src/agent`、`src/projects`、`src/prototypes`、`src/workflows`、`src/integrations`、`src/skills`、`src/contracts`。保持一个构建单元，不提前拆包或微服务。contracts 只承载实际跨模块 DTO 和接口，不建设通用框架。

UI 仅通过类型化 IPC 请求应用服务；工作流依赖 ModelProvider、BrowserPort、DocumentConnector、WorkItemConnector、CredentialStore 接口，平台 SDK 留在适配器内部。扩展点先在构建时注册，不做动态插件系统。

### 2. 本地工作空间与凭证

SQLite 保存 Project、ModelProfile、Connection、TaskRun、StepRun、ArtifactVersion、Approval 和 SyncReceipt；项目文件夹保存 sources、memory、prototypes、documents、workflows。`记忆.md` 作为项目概况与索引。内部对象使用稳定 ID，数据库记录相对路径和内容哈希，文件先写临时文件再原子替换；启动时核对未完成写入并恢复。

Project 绑定一个工作空间，项目切换同时切换任务上下文、平台连接和浏览器 session partition。全局模型配置可由项目引用或覆盖。凭证通过系统钥匙串保存，数据库只存引用；日志、原型、记忆和导出不包含凭证。SQLite schema 使用版本迁移，迁移前备份。

### 3. 模型与执行边界

首批支持 OpenAI-compatible 和 Anthropic API 适配器，配置 endpoint、model、credentialRef 和能力信息。连接测试区分鉴权、模型不存在、网络与能力不足；文本任务不强制要求图像模型。流式事件驱动右侧进度和成果展示。

执行层提供文件、浏览器、原型、文档和平台工具，每次调用绑定 projectId、runId 和工具参数。任务状态为 queued/running/waiting-user/succeeded/failed/cancelled/interrupted；持久化步骤输入引用和产出。应用重启后将运行中的步骤标为 interrupted，通过检查点恢复，不盲目重放平台写入。

本地文件限制在用户选择的工作空间；远程网页和生成原型禁用 Node 集成，启用隔离和 sandbox，不暴露凭证 IPC。网页与交接材料按数据处理，不得覆盖执行权限或确认状态。第三方脚本在独立进程运行，声明所需文件和网络范围；独立进程本身不视作安全沙箱，不能约束的能力须显示并在首次启用前得到授权。

### 4. 浏览器采集与原型重建

使用独立 WebContentsView 承载真实网页，每项目独立持久化登录会话。用户手动登录并处理验证码，Agent 通过受控浏览器接口读取 DOM、可访问性信息、截图和操作结果。先验证 Chromium 自动化附着与登录保持，不额外依赖系统 Chrome。

采集保存 URL、时间、页面状态、截图及观察到的交互。交接材料首批支持 Markdown、纯文本、HTML；其他格式明确提示转存为支持格式。记忆区分已观察、用户确认、推断、待验证，并引用来源。发现冲突保留记录，不静默覆盖确认事实。

以采集依据生成单文件 HTML 原型，CSS、JS 内联，素材本地固定，使用模拟数据。原型运行于独立预览上下文，拦截生产接口写入并默认限制外部网络；普通预览点击与元素选择模式明确切换。元素通过生成时植入的稳定 ID 关联源文件，选中后将 ID、页面状态和截图传给 Agent。修改保存为新候选版本，预览刷新后恢复目标页面状态。

复刻质量以指定页面范围、关键路径可操作和用户视觉验收为准，不承诺任意网页像素级自动还原。验收至少涵盖筛选、弹窗、表单校验、取消、提交结果和相关空态；未观察到的业务逻辑标为假设。

### 5. 版本确认和文档流程

ArtifactVersion 记录 baselineId、contentHash、sourceRefs 和状态。候选自动保存；点击“通过此版本”创建绑定哈希的 Approval，并固定原型版本。通过后继续修改产生新候选，不能沿用旧确认。截图从被批准版本的实际交互状态生成，并记录版本引用。

首次 PRD：确认原型 → 截图与正文草稿 → 用户审阅并发布 → 飞书读回 → 云效状态同步。修改 PRD：读取线上实时内容和修订指纹 → 必要时修改并确认原型 → 生成章节差异评审 → 批准后合并 → 更新共用原型 → 同步状态。纯文字修改无需强制重建原型。合并前再次核对相关章节指纹，变化则重新评审，禁止覆盖并发人工修改。

同一迭代保留一个包含已批准交互的共用原型；需求文档引用迭代文档附件入口，截图保持对应需求评审版本。先在候选副本修改，合并成功后替换共用附件，保留旧版。父级节点不明确时暂停该发布步骤。

平台操作保存远端 ID、版本、内容哈希及阶段结果。为创建操作设置稳定请求标识；遇到超时先查远端状态，无法确认时提示用户核对，禁止自动重复创建。跨平台不承诺事务回滚，按阶段记录部分成功并仅重试失败或未执行步骤。云效状态映射在项目设置配置，文档完成不自动等同需求完成。

### 6. Skill 兼容与安装包

读取 SKILL.md、相对引用和附属脚本，支持导入或选择本地目录；保留来源、版本指纹、工具依赖与兼容状态。将通用文件、浏览器、问答和平台工具映射到 Produck 接口；宿主专用工具显式报告缺失，不伪装成功。

内置产品工作流复用现有 prd-feishu / prd-feishu-edit 的规则，以 Produck 原生工具承接其发布和版本操作，不依赖绝对本机路径或 Agent CLI。脚本使用随包 Node 运行环境；首批确需 Python 的技能配置可分发嵌入式 Python 与固定依赖，构建时收集许可。未打包的外部二进制依赖被标为不支持，不在运行时偷偷安装系统软件。

先提供 macOS arm64 安装包，模块与构建配置保留 x64 路径；Intel 支持在确认设备需求后安排。安装包包含浏览器和首批技能所需资源，无开发环境机器必须完成验收。公开分发前完成签名和公证；开发阶段允许明确标注的未签名测试包。

### 7. 界面与实施顺序

米白底、暖灰边界、深色正文；左侧项目和资料导航，中央浏览器/原型/文档，右侧任务对话；底部显示当前阶段及对应动作。窄窗口可收起导航，失败显示恢复入口，流式执行可取消。

先制作应用本身的交互原型供体验，然后验证登录网页采集和原型重建，再构建核心闭环，最后接平台、技能和安装包。每阶段交付可运行成果，不先搭大量空接口。

## 风险 / 权衡

- 页面复杂、跨域 iframe 或 Canvas 无法提取完整结构 → 截图重建与人工补充，标注覆盖范围，不宣称恢复未见状态。
- 生成原型出现交互回归 → 固定代表页面夹具并点测关键路径，用户按版本验收。
- Electron 与内置运行时增大安装包 → 首版接受体积换取安装即用，按实测精简依赖。
- 模型长任务成本与上下文增长 → 按页面检索记忆、保留任务摘要、限制步骤预算并允许取消。
- 第三方技能环境不一致 → 兼容报告和测试过的内置技能集，限制支持承诺。
- 飞书/云效写入中断或并发编辑 → 指纹校验、阶段收据、读回与可恢复重试。
- 后续分发涉及许可、签名和机器架构 → 发布任务单独验收，不将开发机运行等同可分发。

## 迁移计划

无既有业务数据迁移。按界面原型、核心闭环、平台集成、分发验证逐阶段提交仓库。保存数据库版本与迁移前备份；升级失败保留原文件并恢复备份，原型基线永不被候选覆盖。外部平台写入依赖收据和历史版本修复，不声称卸载或降级能撤销远端动作。

## 待验证事项

- 开发者签名身份、实际设备架构和最低 macOS 版本在打包前确认，不阻塞核心实现。
- 用代表性登录网页验证 WebContentsView 自动化、状态采集与元素定位；结果决定浏览器适配内部实现。
- 首批模型端点和平台测试项目由用户在应用中配置，凭证不进入仓库。
- 对现有 PRD 技能逐项核对依赖和许可，决定原生适配与嵌入运行时的具体清单。

## 2026-11-19：Python 脚本优先

用户选择优先支持 Python 脚本。继续采用随应用提供固定运行时和依赖、显式能力声明及授权、受限文件/网络范围的原设计；系统 Python 不作为分发前提。先验证可分发运行时及 macOS 隔离，再开放第三方脚本执行。

## 2026-11-19：项目下的产品版本

项目拥有模型、工作空间、飞书应用凭证、云效项目连接、共享资料记忆与技能。新增产品版本（release），区别于原型候选修订（artifact version）。版本拥有名称、飞书迭代父节点、原型、PRD、审批、Agent 任务及平台收据。执行入口传入固定版本 ID，不依赖可变的当前选择。

数据库 v3 新增 releases，并为原型与任务补充 release_id；已有项目的默认版本 ID 沿用项目 ID，文件保留原目录，避免移动导致既有收据/哈希失效。新版本文件保存在项目 releases/<id> 下。新项目先创建项目再显式创建版本。项目 ID 的旧执行入口仅兼容已迁移默认版本，新项目没有版本时拒绝执行。共享资料通过显式 shared() 访问，版本文件通过 context() 访问。飞书凭证按项目保存，目标地址从固定版本解析；更改目标使旧发布审阅失效。新版本可以复制同项目旧版原型内容作为未批准候选，不复制批准或发布记录。

## 2026-11-23：云效 AccessKey 兼容

按用户要求优先支持现有 AK 配置。新配置默认 AK，既有未声明 authType 的配置继续按 PAT 解释。AK ID 与 Secret 成对保存在系统钥匙串，配置仅存 authType 和凭证引用；切换认证方式或更换 AK 必须重新填写成对凭证。使用云效 2021-06-25 ROA API 与 ACS3-HMAC-SHA256 签名，固定 devops.cn-hangzhou.aliyuncs.com，不依赖系统 SDK/CLI。工作项状态流按实际工作项读取；保持原有显式确认、持久写入意图、无自动重发与读回策略。真实验收仅执行项目和工作项读取，状态写入使用模拟平台验证。

## 2026-11-23：批量元素修改

在右侧拾取多个元素，每个稳定 ID 对应一个独立 prompt，最多 12 项。预览隔离世界排队记录点击，避免轮询丢失连续选择。提交携带基线版本及内容哈希，主进程检查当前预览，生成器解析基线验证唯一元素。动态生成且未写入基线的元素需要选择固定父区域。不改变旧版，统一生成一个候选；检查点和变更详情保存完整绑定。失败保留输入，切换原型清空旧选择。左侧显式收起，标题栏保留展开入口。

2026-11-24 界面微调：按用户要求移除左栏重复的「收起左侧」按钮，仅保留标题栏原有收起/展开入口。

## 2026-11-25：模型选择

按当前 endpoint/provider/token 请求 models 列表，保存凭证仅可用于原供应商与原地址。列表失败保留手动输入；不按名称猜测能力。OpenAI-compatible 可选 reasoning_effort，默认省略；非默认档位由模型和代理支持情况决定，需测试。Anthropic 暂只支持默认。数据库 v4 增加字段，旧配置保持默认；所有任务经统一 ModelService 继承。
