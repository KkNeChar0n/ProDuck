## ADDED Requirements

### 需求:安装即可使用
应用必须提供 macOS 安装包并携带核心工作流的运行依赖，不得要求安装开发工具或 Agent CLI。

#### 场景:干净机器启动
- **当** 在受支持架构与系统版本、未安装 Node/Python/Agent CLI 的 Mac 安装并配置有效模型
- **那么** 能够创建项目并执行一次原型生成；缺少飞书配置仅影响平台发布

### 需求:项目与连接隔离
系统必须为每个项目绑定独立工作空间、平台配置与浏览器会话。

#### 场景:切换项目
- **当** 用户从项目 A 切换到 B
- **那么** 仅加载 B 的文件、记忆、任务与连接；不得将 A 的凭证或登录会话用于 B

### 需求:工作台导航
工作台必须提供米白色三栏布局、浏览器/原型/文档切换和阶段动作。

#### 场景:修改原型
- **当** 用户进入原型任务
- **那么** 中央显示可操作页面，右侧提供 prompt 输入、进度和取消入口，并可收起导航

### 需求:持久化与恢复
系统必须保存项目和成果索引，并在存储失败时保留此前有效版本。

#### 场景:重启与写入中断
- **当** 保存过程中应用中断后重启
- **那么** 恢复此前完整版本或完成已验证的原子写入，不把残缺文件标记为成功

### 需求:项目产品版本
项目必须支持创建和切换产品版本；模型、工作空间及云效连接归项目，飞书迭代父节点归版本。

#### 场景:版本切换
- **当** 用户从同项目版本 A 切换至 B
- **那么** B 共享项目模型与资料，但只展示 B 的原型、文档及任务；A 的运行任务仍写入 A

#### 场景:旧项目迁移
- **当** 打开升级前项目
- **那么** 原成果归入默认版本，文件和批准收据不被修改，原飞书地址归入默认版本

#### 场景:新版本起点
- **当** 用户选择同项目旧原型作为新版本起点
- **那么** 复制内容为独立未批准候选，不继承旧批准或远端发布记录
