## ADDED Requirements

### 需求:原型先行生成文档
系统必须在原型通过后生成对应 PRD 正文和截图，并绑定同一批准版本。

#### 场景:未通过原型
- **当** 用户仍在调整候选
- **那么** 保持原型阶段，不自动生成最终 PRD 或发布平台

### 需求:首次发布与读回
系统必须提供文档审阅和发布动作，并在写入后读回确认正文、截图和链接。

#### 场景:首次发布
- **当** 用户发布已审阅草稿
- **那么** 飞书内容和附件验证成功后才进入云效同步

### 需求:实时差异评审
系统必须基于线上实时文档制作章节差异，保留无关内容，合并前校验被改章节未发生并发修改。

#### 场景:评审后他人修改
- **当** 用户批准差异后检测到目标章节变化
- **那么** 停止该章节合并并重新生成差异，禁止覆盖人工更新

### 需求:分离确认
系统必须区分原型确认和文档差异批准；纯文字修改不强制原型调整。

#### 场景:仅通过原型
- **当** 用户通过涉及页面修改的原型
- **那么** 可以生成文档评审，但未经文档批准不得合并线上 PRD

### 需求:迭代共用原型
系统必须在迭代文档维护一个共用 HTML 附件，需求引用其入口并保留各自评审截图。

#### 场景:更新一个需求
- **当** 本迭代另一个需求已有批准交互
- **那么** 候选保留该交互，合并成功后替换同一附件并保留回滚版本；父级不明时暂停发布

### 需求:阶段恢复与状态映射
系统必须记录各平台步骤结果，按项目配置映射云效状态，支持部分失败恢复。

#### 场景:云效同步失败
- **当** PRD 和附件成功但云效请求失败
- **那么** 显示部分完成，重试仅处理未完成步骤，不重复创建文档；无映射时不擅自标记需求已完成

### 需求:不确定远端结果
系统必须在写请求超时后核对远端结果再决定重试。

#### 场景:创建请求超时
- **当** 飞书可能已创建文档但未返回结果
- **那么** 通过稳定标识查询；无法确认时标为待核对，不自动重复创建

### 需求:云效 AK 认证
系统必须支持项目级 AccessKey ID/Secret，并保留已有 PAT 配置。

#### 场景:保存 AK
- **当** 用户选择 AK 并填写成对凭证
- **那么** 凭证仅存钥匙串，连接测试读取所配置的项目，失败不得宣称成功

#### 场景:更新结果不明
- **当** AK 状态更新请求超时
- **那么** 保存待核对结果，恢复仅执行读回，不自动重发更新
