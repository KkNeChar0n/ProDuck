## ADDED Requirements

### 需求:可操作高保真原型
系统必须根据选定页面证据生成本地可操作原型，保留主要视觉结构和已约定交互，使用模拟数据。

#### 场景:列表与表单复刻
- **当** 用户采集包含筛选和新增弹窗的页面
- **那么** 原型支持筛选、打开关闭弹窗、必填校验、取消和成功反馈，未核实行为标为假设

### 需求:真实网页与原型隔离
系统必须明确区分真实浏览器与原型模式，原型禁止调用生产写接口。

#### 场景:点击原型提交
- **当** 用户提交模拟表单
- **那么** 仅修改模拟状态，真实系统未收到业务写请求

### 需求:元素提示修改
系统必须支持页面级和元素级 prompt 修改，选择模式不得与交互体验模式混淆。

#### 场景:定向修改
- **当** 用户选中筛选区域并要求增加状态筛选
- **那么** 生成新候选版本并展示修改说明，其他已确认页面仍保留

### 需求:版本确认与撤销
系统必须保存不可变基线和候选版本，并将通过动作绑定内容哈希。

#### 场景:通过后再修改
- **当** 已通过的原型发生进一步修改
- **那么** 保留旧确认版本，新内容成为未确认候选，不能用旧确认生成对应最终 PRD

### 需求:版本恢复
系统必须提供版本对比和恢复且不覆盖历史基线。

#### 场景:放弃候选
- **当** 用户恢复修改前版本
- **那么** 当前候选内容与所选基线一致，历史版本和线上文档保持可追溯

### 需求:原型交互检查
系统必须记录候选原型的关键路径检查结果，失败时不得显示检查成功。

#### 场景:按钮无响应
- **当** 检查发现提交按钮无法产生预期结果
- **那么** 报告失败步骤，允许修复后重新检查和用户验收
